# Question 13 — NetworkPolicy Lab

## Exact task

There are two deployments, Frontend and Backend. Frontend is in the frontend namespace, Backend is in the backend namespace.

Task:

- Inspect the NetworkPolicy YAML files in /root/network-policies.
- Choose the policy that allows frontend-to-backend communication in the least permissive way.
- Deploy that YAML without deleting or modifying any existing deny-all policies.

## Initial setup

```bash
echo "🔹 Creating namespaces..."
kubectl create namespace frontend --dry-run=client -o yaml | kubectl apply -f -
kubectl create namespace backend --dry-run=client -o yaml | kubectl apply -f -

echo "🔹 Deploying backend app..."
kubectl apply -n backend -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend-deployment
  namespace: backend
spec:
  replicas: 1
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      containers:
      - name: backend
        image: nginx
        ports:
        - containerPort: 80
EOF

echo "🔹 Exposing backend as ClusterIP service..."
kubectl expose deployment backend-deployment -n backend --port=80 --target-port=80 --name=backend-service

echo "🔹 Deploying frontend app..."
kubectl apply -n frontend -f - <<EOF
apiVersion: apps/v1
kind: Deployment
metadata:
  name: frontend-deployment
  namespace: frontend
spec:
  replicas: 1
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: frontend
        image: curlimages/curl
        command: ["sleep", "3600"]
EOF
```

## Create the candidate policies

```bash
echo "🔹 Creating NetworkPolicy files..."
mkdir -p /root/network-policies
cd /root/network-policies

cat <<EOF > network-policy-1.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: policy-x
  namespace: backend
spec:
  podSelector: {}
  ingress:
  - {}
  policyTypes:
  - Ingress
EOF

cat <<EOF > network-policy-2.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: policy-y
  namespace: backend
spec:
  podSelector:
    matchLabels:
      app: backend
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: frontend
    - ipBlock:
        cidr: 172.16.0.0/16
    ports:
    - protocol: TCP
      port: 80
  policyTypes:
  - Ingress
EOF

cat <<EOF > network-policy-3.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: policy-z
  namespace: backend
spec:
  podSelector:
    matchLabels:
      app: backend
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: frontend
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 80
  policyTypes:
  - Ingress
EOF
```

## Solution

Compare the policies and select the one that is restrictive enough while still allowing the required communication.

```bash
# policy-x: too open because it allows all ingress
# policy-y: still too open because it also allows an IP range
# policy-z: the best fit because it allows only frontend namespace/pods on TCP 80

kubectl get pods -n frontend --show-labels
kubectl apply -f /root/network-policies/network-policy-3.yaml
```

## Correct policy

Use this policy:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: policy-z
  namespace: backend
spec:
  podSelector:
    matchLabels:
      app: backend
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: frontend
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 80
  policyTypes:
  - Ingress
```

## Why this is correct

- Policy 1 is too permissive because it allows all ingress.
- Policy 2 is still broader than needed because it permits traffic from an extra IP block.
- Policy 3 is the least permissive option that still allows the frontend deployment in the frontend namespace to reach the backend deployment on port 80.

> Extra note: In a real exam, always verify that the pod labels match the selectors in the NetworkPolicy. If the labels differ, the policy will not allow the intended traffic.
