# StorageClass Task Reference

## Exact Question
Create a new StorageClass named `local-storage` with the provisioner `rancher.io/local-path`.

Requirements:
- Set `volumeBindingMode` to `WaitForFirstConsumer`
- Do not make the StorageClass default initially
- Patch the StorageClass so it becomes the default StorageClass
- Ensure `local-storage` is the only default StorageClass by removing the default annotation from any other existing StorageClass
- Do not modify any existing Deployments or PersistentVolumeClaims

## How to replicate this in Killer Koda

1. Start a Kubernetes cluster with a working StorageClass provider.
2. List current StorageClasses:

```bash
kubectl get storageclass
```

3. Create the new StorageClass without marking it as default:

```bash
cat <<EOF | kubectl apply -f -
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: rancher.io/local-path
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Delete
EOF
```

4. Remove the default annotation from any existing default StorageClass.
5. Mark `local-storage` as the default StorageClass.
6. Verify the result.


## Office-Doc Reference Solution

### Step 1: Check the current StorageClasses

```bash
kubectl get sc
```

### Step 2: Create the new StorageClass

```bash
cat <<EOF | kubectl apply -f -
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: rancher.io/local-path
volumeBindingMode: WaitForFirstConsumer
reclaimPolicy: Delete
EOF
```

> Important: do not add the default annotation at this stage.

### Step 3: Remove the default marker from any other existing StorageClass

```bash
kubectl patch storageclass <existing-default-sc-name> \
  -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
```

### Step 4: Make `local-storage` the default StorageClass

```bash
kubectl patch storageclass local-storage \
  -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
```

### Step 5: Verify the result

```bash
kubectl get sc
kubectl describe storageclass local-storage | grep -i default
```

## Notes for the Exam
- `WaitForFirstConsumer` delays volume binding until a pod using the PVC is scheduled.
- The default StorageClass affects future PVCs that do not specify a class.
- This task should not require changing Deployments or PVCs directly.
- The default annotation key is:

```bash
storageclass.kubernetes.io/is-default-class
```
