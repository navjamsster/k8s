# NodePort Deployment Task

## Objective
Fix the `nodeport-deployment` in the `relative` namespace so that:

- the deployment exposes port `80` on the container
- the container port uses `name=http` and `protocol=TCP`
- a `NodePort` service named `nodeport-service` exposes the deployment on `30080`
- the service selector routes traffic to the deployment pods

## Initial setup

```bash
kubectl create namespace relative

# Create the starting deployment with no ports defined.
kubectl create deployment nodeport-deployment \
  --image=nginx \
  --replicas=2 \
  -n relative
```

Verify the initial state:

```bash
kubectl get deployment nodeport-deployment -n relative
kubectl describe deployment nodeport-deployment -n relative | grep -i port
```

> Expected: no ports should appear in the deployment spec. This is the issue we need to fix.

## Solution

### 1. Add container port configuration to the deployment

Inspect the deployment containers section:

```bash
kubectl describe deployment nodeport-deployment -n relative | grep -A5 "Containers"
```

Then edit the deployment:

```bash
kubectl edit deployment nodeport-deployment -n relative
```

Add the `ports:` block to the container spec.

```yaml
# BEFORE:
spec:
  containers:
  - name: nodeport-deployment
    image: nginx

# AFTER:
spec:
  containers:
  - name: nodeport-deployment
    image: nginx
    ports:
    - name: http          # name required by the task
      containerPort: 80   # required port
      protocol: TCP       # required protocol
```

> Note: adding `ports:` is not technically required for the service to work, but the question explicitly expects the container port to be defined this way.

Confirm the updated deployment:

```bash
kubectl describe deployment nodeport-deployment -n relative | grep -i port
```

### 2. Check the deployment labels

The service selector must match the deployment pod labels. Verify them with:

```bash
kubectl get deployment nodeport-deployment -n relative --show-labels
```

> Example label: `app=nodeport-deployment`

### 3. Create the NodePort service

Generate a service manifest with dry-run and edit it:

```bash
kubectl expose deployment nodeport-deployment \
  --name=nodeport-service \
  --port=80 \
  --target-port=80 \
  --protocol=TCP \
  --type=NodePort \
  -n relative \
  --dry-run=client -o yaml > nodeport-svc.yaml

vi nodeport-svc.yaml
```

Edit `nodeport-svc.yaml` to match the required service definition:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nodeport-service        # exact name required
  namespace: relative           # must match namespace
spec:
  type: NodePort
  selector:
    app: nodeport-deployment    # must match deployment labels
  ports:
  - name: http
    protocol: TCP               # required protocol
    port: 80                    # service port
    targetPort: 80              # container port
    nodePort: 30080             # specific NodePort required
```

Apply the service manifest:

```bash
kubectl apply -f nodeport-svc.yaml
```

> Tip: `port` is the service port, `targetPort` is the container port, and `nodePort` is the external node port.

## Example manifests

### Deployment manifest

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nodeport-deployment
  namespace: relative
spec:
  replicas: 2
  selector:
    matchLabels:
      app: nodeport-deployment
  template:
    metadata:
      labels:
        app: nodeport-deployment
    spec:
      containers:
      - name: nodeport-deployment
        image: nginx
        ports:
        - name: http
          containerPort: 80
          protocol: TCP
```

### Service manifest

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nodeport-service
  namespace: relative
spec:
  type: NodePort
  selector:
    app: nodeport-deployment
  ports:
  - name: http
    protocol: TCP
    port: 80
    targetPort: 80
    nodePort: 30080
```

### 4. Verify the service

```bash
kubectl get svc nodeport-service -n relative
kubectl describe svc nodeport-service -n relative
kubectl get endpoints nodeport-service -n relative
```

### 5. Confirm Node and pod accessibility

Get node IP addresses:

```bash
kubectl get nodes -o wide
```

Verify all resources in the namespace:

```bash
kubectl get all -n relative -o wide
```

## Testing

- Test NodePort access from any node:

```bash
curl http://<NODE-IP>:30080
```

- Test service ClusterIP access on port 80:

```bash
curl http://<SERVICE-CLUSTER-IP>:80
```

> The service should work via `ClusterIP:80`. It should not work on `ClusterIP:30080`, because the service port is `80`, not `30080`.

- Verify endpoint pod IPs and ports:

```bash
kubectl get endpoints -n relative
kubectl get endpointslice -n relative
```

Direct pod access examples:

```bash
curl http://192.168.1.119:80
curl http://192.168.1.85:80
```

> NodePort `30080` exposes traffic on each node IP. The service ClusterIP exposes traffic on port `80` only.
