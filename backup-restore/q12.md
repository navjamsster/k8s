# Question 12 — Ingress Lab

## Task

Create a new Ingress resource named `echo` in the `echo-sound` namespace.

Complete the following tasks:

- Expose the deployment with a Service named `echo-service`
- Make it reachable at `http://example.org/echo`
- Configure the Service to use port `8080`
- Set the Service type to `NodePort`

You can verify the result with:

```bash
curl -o /dev/null -s -w "%{http_code}\n" http://example.org/echo
# Expected output: 200
```

## Initial setup

```bash
# Create namespace
kubectl create namespace echo-sound

# Deploy the echo application
kubectl create deployment echo \
  --image=ealen/echo-server \
  --replicas=1 \
  -n echo-sound

# Verify deployment
kubectl get deployment echo -n echo-sound
kubectl get pods -n echo-sound
```

### Check ingress controller

```bash
# Check whether an ingress controller already exists
kubectl get ingressclass
```

If nothing is shown, install the NGINX ingress controller:

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.0/deploy/static/provider/cloud/deploy.yaml
```

Wait until the controller is ready:

```bash
kubectl wait --namespace ingress-nginx \
  --for=condition=ready pod \
  --selector=app.kubernetes.io/component=controller \
  --timeout=90s
```

Verify the ingress class:

```bash
kubectl get ingressclass
# Expected: nginx   k8s.io/ingress-nginx
```

## Solution

### 1) Inspect the current state

```bash
# Check existing resources in the namespace
kubectl get all -n echo-sound
kubectl get deployment echo -n echo-sound
kubectl get svc -n echo-sound
```

### 2) Create the Service

The Service must match the deployment and expose the correct port.

```bash
# Create the Service YAML using dry-run
kubectl expose deployment echo \
  --name=echo-service \
  --port=8080 \
  --target-port=8080 \
  --type=NodePort \
  -n echo-sound \
  --dry-run=client -o yaml > echo-svc.yaml
```

Example Service manifest:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: echo-service
  namespace: echo-sound
spec:
  type: NodePort
  selector:
    app: echo
  ports:
  - port: 8080
    targetPort: 8080
    protocol: TCP
```

Apply it:

```bash
kubectl apply -f echo-svc.yaml
```

Verify:

```bash
kubectl get svc echo-service -n echo-sound
```

### 3) Create the Ingress resource

This step is required before testing the path.

```bash
# Make sure the ingress class name is known before creating the Ingress
kubectl get ingressclass
```

Create the file:

```bash
cat > echo-ingress.yaml <<'EOF'
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: echo
  namespace: echo-sound
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  rules:
  - host: example.org
    http:
      paths:
      - path: /echo
        pathType: Prefix
        backend:
          service:
            name: echo-service
            port:
              number: 8080
EOF
```

Apply it:

```bash
kubectl apply -f echo-ingress.yaml
```

Verify:

```bash
kubectl get ingress echo -n echo-sound
kubectl describe ingress echo -n echo-sound
```

### 4) Add an entry to /etc/hosts

This is needed so the browser or curl can resolve `example.org` to the ingress controller IP.

```bash
# Get the ingress controller IP
kubectl get svc -n ingress-nginx

INGRESS_IP=$(kubectl get svc ingress-nginx-controller \
  -n ingress-nginx \
  -o jsonpath='{.status.loadBalancer.ingress[0].ip}')

# If there is no external IP in the environment, use the node IP instead
if [ -z "$INGRESS_IP" ]; then
  INGRESS_IP=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[0].address}')
fi

echo "$INGRESS_IP example.org" | sudo tee -a /etc/hosts
```

Verify the hosts entry:

```bash
cat /etc/hosts | grep example.org
```

## Final verification

```bash
curl -o /dev/null -s -w "%{http_code}\n" http://example.org/echo
# Expected output: 200
```

## Notes

- The Service name must match the Ingress backend service name exactly.
- The path `/echo` must match the path defined in the Ingress rule.
- The ingress class name must match the installed controller, usually `nginx`.
- The rewrite annotation is important so the request is routed correctly to the app endpoint.
